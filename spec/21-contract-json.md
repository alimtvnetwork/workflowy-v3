### Identifier rules

| Identifier | Pattern | Canonical source file |
|---|---|---|
| Acceptance test | `AT-<SECTION>-NN` (e.g. `AT-MIRRORS-01`) | The owning `9{7,8}-acceptance-criteria.md` |
| Endpoint | `EP-<DOMAIN>-<VERB>` (e.g. `EP-ITEMS-LIST`) | A `## EP-… — METHOD \`path\`` heading under `spec/31-app/06-endpoints/` |
| Enum | PascalCase ending in `Type` (or domain noun) | `spec/20-enums-index.md` table row |
| Section | Two-digit prefix `NN-<slug>` | `spec/<NN-slug>/00-overview.md` |

### Canonical-file rule for AT collisions

When the same `AT-XXX-NN` id appears as a defined row in multiple files, the generator prefers the row in `9{7,8}-acceptance-criteria.md` as authoritative. The other occurrences are demoted to `cited_in[]`. Two non-canonical definitions of the same id fail the build.

### Orphan citations

`orphan_at_citations[]` lists every `AT-…` referenced inline (cross-references, traceability matrices) that has NO defining row in any acceptance-criteria file. These are surfaces for the P10 audit re-runner — every orphan is a missing acceptance test.
