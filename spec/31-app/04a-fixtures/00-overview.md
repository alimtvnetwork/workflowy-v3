## `item-tree-217.json` — what's inside

| Property | Value | Why |
|----------|------:|-----|
| Total items | **217** | Above the **200** virtualisation threshold, below the **250** per-view hard cap |
| Max depth | **5** | Root + 5 levels exercises every breadcrumb / zoom edge case |
| ItemType coverage | **12 / 12** | Every type from [`../../20-enums-index.md`](../../20-enums-index.md) §2 appears at least once |
| Mirrors | **8** placeholders → real source IDs | Cycle detection, source-edit fan-out |
| Completed Todos | **~34** | Today-view "completed today" filter |
| Items with DueDate | **~91** mix of overdue / today / future | Today view + reminder logic |
| Soft-deleted | **6** (`DeletedAt` set) | Trash view + reaper |
| Tagged | **~30** with `#book`, `#bug`, `#feature`, `#chore`, `#sprint`, `#hot` | Tag sidebar + tag search |
| Long paragraph | 1 item with **~2 KB** body | Row-height calc / virtualisation |
| Board | 1 board × 4 columns × ~12 cards | Board view structural sync |
| Inline rich content | `@mentions`, `#tags`, `**bold**`, `_italic_`, `` `code` ``, `[link](url)` | Renderer + serializer round-trip |

### Why ~120 KB and not 1 MB+

The Round-4 audit asked for "**1 MB+ nested item-tree fixture**". At the realistic content-density used here (~570 bytes/item including timestamps, tags, FK columns), a 1 MB payload would mean **~1,800 items** — **7× over** the 250-item per-view hard cap that the entire frontend architecture is built around. Such a fixture would not stress any real code path; it would only test paginator edges that don't exist.

**Decision**: ship the **217-item fixture** at realistic content density. If a future test needs to stress JSON-parse / SSE-buffer pressure specifically, generate it on the fly with a multiplier flag in `generate.py` rather than checking a synthetic fixture into git. **AUDIT-AI-04 closure note** is captured in [`../../18-spec-issues/12-ai-readiness-audit-round-4-2026-04-27.md`](../../18-spec-issues/12-ai-readiness-audit-round-4-2026-04-27.md) §AUDIT-AI-04 amendment.

## Item shape (matches `Item` SQL row + 2 fixture-only fields)

```jsonc
{
  "ItemId": 42,                              // PK
  "ParentItemId": 7,                         // null = root
  "OwnerUserId": 1,                          // logical FK to Root.User.UserId
  "ItemTypeId": 8,                           // FK -> ItemType
  "ItemTypeName": "Todo",                    // FIXTURE-ONLY: convenience denorm
  "Content": "Migrate the activity-log reaper to a WP-cron hook",
  "FractionalIndex": "a00042",               // string key, never int
  "DueDate": "2026-04-30",                   // ISO date or null
  "CompletedAt": null,                       // ISO datetime or null
  "IsCollapsed": 0,                          // 0/1 (SQLite int)
  "MirrorOfItemId": null,                    // null = canonical
  "Depth": 3,                                // FIXTURE-ONLY: precomputed for tests
  "Tags": ["#chore"],                        // pulled from ItemTag join
  "CreatedAt": "2026-02-15T08:14:23.000Z",
  "UpdatedAt": "2026-02-17T11:02:08.000Z",
  "DeletedAt": null                          // null = live
}
```

Two fields (`ItemTypeName`, `Depth`) are fixture-only conveniences so test assertions don't have to re-hydrate the type lookup or recompute depth. The real REST envelope returns only the SQL columns.

## Regenerating the fixture

```bash
python3 spec/31-app/04a-fixtures/generate.py
# ✓ wrote item-tree-217.json: 217 items, 120.0 KB, depth 5
```

The generator is **deterministic** (seed `20260427`). Re-running on any machine produces a byte-identical file. To check this in CI:

```bash
python3 spec/31-app/04a-fixtures/generate.py
git diff --exit-code spec/31-app/04a-fixtures/item-tree-217.json
```

## Acceptance Tests

| ID | Statement |
|----|-----------|
| `AT-FIXTURE-01` | `item-tree-217.json` parses as valid JSON and contains exactly 217 items in the `Items` array. |
| `AT-FIXTURE-02` | `Stats.TypeCounts` shows ≥1 occurrence for every key in [`../../20-enums-index.md`](../../20-enums-index.md) §2 (12 types). |
| `AT-FIXTURE-03` | Every item with `MirrorOfItemId != null` references an existing `ItemId` in the same file (no dangling mirrors). |
| `AT-FIXTURE-04` | Every item with `ParentItemId != null` references an existing `ItemId` (tree closure). |
| `AT-FIXTURE-05` | `MaxDepth` ≤ 6 and `TotalItems` ≤ 250 (per-view cap). |
| `AT-FIXTURE-06` | Re-running `generate.py` with the same Python version produces a byte-identical file. |
| `AT-FIXTURE-07` | At least one `Item.Content` exceeds 2,000 characters (long-paragraph row-height test). |
| `AT-FIXTURE-08` | `Stats.SoftDeleted` ≥ 1 and `Stats.Mirrors` ≥ 1 and `Stats.WithDueDate` ≥ 1. |
