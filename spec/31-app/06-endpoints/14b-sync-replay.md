# Endpoints — 14b Sync Replay (Offline Queue)

## Database Routing

**Read:** App DB (per-workspace; one SQLite file per workspace) — `Items` for replay-after-restart materialization.
**Write:** App DB (per-workspace; one SQLite file per workspace) — drained queue mutations write to `Items` per the originating endpoint's routing.
**Client mirror:** IndexedDB (per ADR-0021/0023; not a server DB).

## EP-SYNC-REPLAY — POST `sync/replay`

- **Auth**: `user`. Per-mutation ACLs are re-validated server-side; offline edits to since-revoked items are rejected individually, not fatally.
- **Request body**:
  ```json
  {
    "ClientId": "uuid",
    "BatchId": "uuid",
    "Mutations": [
      {
        "OpId": "uuid",
        "ItemId": "string",
        "Op": "create" | "update" | "delete" | "move",
        "Payload": { /* op-specific */ },
        "ClientUpdatedAt": "ISO-8601"
      }
    ]
  }
  ```
  - `Mutations` MUST be in **FIFO order** as queued on the client (per `mem://features/offline-resilience`) (per AT-APP-100 + ADR-0023).
  - Max **500 mutations per batch**; clients chunk larger queues.
- **Success (200)** `Results`:
  ```json
  {
    "BatchId": "uuid",
    "Applied": ["OpId", ...],
    "Conflicts": [
      {
        "OpId": "uuid",
        "Reason": "lww-stale" | "forbidden" | "not-found" | "parent-full" | "mirror-broken",
        "ServerItem": { /* current Item, if any */ }
      }
    ],
    "Cursor": "string"
  }
  ```
- **LWW rule**: per mutation, if `ServerItem.UpdatedAt > Mutation.ClientUpdatedAt`, the mutation is rejected with `lww-stale` and the client adopts `ServerItem`. Uses `IdxItem_UpdatedAt` for the comparison lookup.
- **Errors** (batch-fatal): `ERR_BATCH_TOO_LARGE`, `ERR_INVALID_BATCH`, `ERR_UNAUTHENTICATED`. Per-mutation failures are returned in `Conflicts`, NOT as HTTP errors.
- **Side effects**:
  - Applied mutations emit standard SSE events (`item-updated`, `item-deleted`, etc.) on the per-page (`/stream/page/{id}`) and per-user (`/stream/user/{id}`) topics defined by ADR-0025.
  - `Cursor` advances to the highest event ID generated by the batch — clients pass it to subsequent `EP-SYNC-POLL` / `EP-SYNC-STREAM` calls.
- **Idempotency**: `(ClientId, OpId)` is unique server-side. Re-submitting the same batch returns the prior outcome without re-applying.
- **AC refs**: `AT-APP-97`, `AT-APP-98`, `AT-APP-99`, `AT-APP-100`, `AT-APP-101`, `AT-APP-102`.
