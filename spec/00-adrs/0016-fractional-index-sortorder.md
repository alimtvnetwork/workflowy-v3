# ADR-0016: Fractional-index `SortOrder` — lexicographic string, midpoint split, threshold-triggered rebalance

## Status

`Accepted` — 2026-04-28

## Context

Sibling ordering is referenced in at least seven spec surfaces
(`AT-APP-04`, `AT-INTERACT-06`, `AT-CTXMENU-13`, `AT-INFOMODEL-09/10`,
`07-board-view.md`, `19-glossary.md` "Fractional sort key", and
`mem://features/editor-core`) but the algorithm definition is
**contradictory**:

- `mem://features/editor-core` describes a **numeric** midpoint
  `(A + B) / 2` with rebalance trigger at gap `< 0.0001`.
- `spec/19-glossary.md` line 89 and `AT-APP-04` examples describe a
  **lexicographic string** key (`"a0"`, `"a1"`, `"a2"`, `"a0V"`) —
  Workflowy / Figma / LexoRank style.
- `spec/31-app/01-features/01-information-model.md:92` types `sortOrder`
  as `number (fractional)` — contradicting both the glossary and
  `Item.SortOrder` DDL implications.

Three contradictory shapes (`number` decimal, lexicographic `string`,
integer `int` from the Go enum example) cannot all be implemented; AI
implementers have legitimately reached for `(A+B)/2` floats because the
memory rule says so, then hit float-precision rebalance storms at
sibling depth ~50 — exactly the failure mode the string algorithm exists
to prevent. ADR-0008's `Node.sortOrder` left the runtime shape open.
This ADR closes it.

## Decision

`Item.SortOrder` is a **lexicographic string** generated by a
base-62 fractional-index algorithm. The numeric `(A+B)/2` description in
`mem://features/editor-core` is hereby **superseded** and MUST be (gate G-21-NO-NUMERIC-MIDPOINT)
corrected.

**D1 — Storage shape.** `Item.SortOrder` is `TEXT NOT NULL` in SQLite,
`string` in TypeScript, and `string` on the wire. Numeric `number` /
`int` representations are forbidden. Type-defs in
`spec/31-app/01-features/01-information-model.md` line 92 and any
`int SortOrder` example are stale and MUST be corrected to `string` (gate G-21-NO-NUMERIC-MIDPOINT).

**D2 — Alphabet.** The key uses base-62 lexicographic-safe digits in
ASCII order: `0-9` < `A-Z` < `a-z` (62 symbols). Comparison is plain
byte-wise lexicographic (`ORDER BY SortOrder ASC` in SQLite default
collation, `<` in JS/TS). No locale-aware collation. No Unicode
characters above U+007E.

**D3 — Generation rules.**
- **First child (empty parent):** `"a0"`.
- **Append after last sibling `S`:** `S + "1"` (suffix the smallest
  digit greater than the alphabet's zero — `"a0"` → `"a01"`).
- **Prepend before first sibling `F`:** decrement `F`'s last digit if
  possible; otherwise `"Z" + (F shifted)` — implementation MUST (gate G-21-NO-NUMERIC-MIDPOINT)
  guarantee the produced key is `<` `F` lexicographically.
- **Insert between `A` and `B` (`A < B`):** produce a key `K` such that
  `A < K < B`. The standard algorithm: walk both keys digit-by-digit;
  on the first differing position, pick the midpoint digit; if no
  midpoint exists (adjacent digits like `"a"` and `"b"`), append a
  midpoint suffix to `A`. Reference algorithm:
  `mudder.js` / Figma's fractional-indexing crate.

**D4 — Stability.** Inserting an item between siblings MUST mutate
**only** the new item's `SortOrder`. Sibling rows MUST remain untouched
(verified by `AT-APP-04` side-effects clause). Bulk reorders MUST be
single-row writes per item, not full-list renumbering.

**D5 — Rebalance trigger and policy.**
- Rebalance is triggered when any newly-generated key would exceed
  **64 bytes** in length, OR when the count of consecutive
  midpoint-suffix appends to the same key prefix exceeds **6** within a
  single insert cluster.
- Rebalance scope: only the children of the affected `ParentId`, never
  the whole table.
- Rebalance algorithm: redistribute `n` siblings as
  `"a0"`, `"a1"`, …, `"a9"`, `"aA"`, … walking the alphabet, capped at
  one digit; for `n > 62`, use two digits.
- Rebalance MUST be a single transaction and MUST emit one (gate G-21-NO-NUMERIC-MIDPOINT)
  `SortOrderRebalanced` audit event per parent (replay-safe under
  ADR-0010's FIFO queue).
- The `< 0.0001` numeric threshold in `mem://features/editor-core` is
  **superseded** and meaningless under string keys.

**D6 — Concurrency.** Two clients computing the same insertion slot
MUST be tolerated: both keys may collide (identical string) or (gate G-21-NO-NUMERIC-MIDPOINT)
interleave (different strings in the same slot). Tiebreak follows
ADR-0010's field-level LWW on `(ServerTs, UserId)`; on identical
`SortOrder` strings, lexicographic `Item.Id` is the final tiebreak.
Clients MUST NOT assume `SortOrder` is unique within a parent (gate G-21-NO-NUMERIC-MIDPOINT).

**D7 — Wire and DDL.** REST envelope (per ADR-0004) serialises the
field as `"SortOrder": "a0V"` (PascalCase key, string value).
SQLite column: `SortOrder TEXT NOT NULL` (singular DDL per ADR-0001).
Index: `CREATE INDEX Item_ParentId_SortOrder ON Item(ParentId, SortOrder)`
to enforce the standard child-listing query path.

## Consequences

**Positive**

- Eliminates the float-precision rebalance storm at deep sibling
  insertion that the numeric `(A+B)/2` rule guarantees after ~50
  midpoint splits.
- Inserts are O(1) writes (one row), reorders are O(1) writes per
  moved item — matches Workflowy's actual perf characteristic.
- String comparison is portable across SQLite, JS, and PHP without any
  numeric-precision divergence between languages.
- Closes the `number` vs `string` vs `int` contradiction across four
  spec files.
- Bounded key length (64 bytes) keeps the column index small.

**Negative**

- Memory file `mem://features/editor-core` is now stale (numeric rule)
  and MUST be rewritten as a follow-up (gate G-21-NO-NUMERIC-MIDPOINT).
- `spec/31-app/01-features/01-information-model.md` line 92 must be
  corrected from `number (fractional)` to `string (fractional, base-62)`.
- The "rebalance at gap < 0.0001" rule is now meaningless and must be
  excised from prose, hotkey docs, and any AT scenarios that cite it.
- AI implementers must use a fractional-indexing library
  (e.g. `fractional-indexing`, `mudder`) instead of writing
  `(a + b) / 2`; hand-rolling the string-midpoint is bug-prone.


**Spec impact** — Downstream sections affected by this decision: [`spec/31-app/ (SortOrder)`](../31-app/).

## Alternatives Considered

1. **Numeric `(A+B)/2` (current `editor-core` memory)** — rejected:
   IEEE-754 doubles run out of precision after ~50 consecutive
   midpoint inserts; any real outliner hits this on day 1. Forces
   full-sibling-renumber rebalances, which violate D4 and break
   collaborative cursors.
2. **Integer `SortOrder` with sparse gaps (1000, 2000, 3000…)** —
   rejected: every insert that exhausts the gap forces an
   O(n) renumber of all later siblings, which violates D4 and
   thrashes the FIFO queue under ADR-0010 (every renumbered row is a
   write op).
3. **LexoRank exact (Atlassian)** — rejected as the *named* algorithm
   only; LexoRank's bucket prefix (`0|`, `1|`, `2|`) is unnecessary
   for our scale (per-parent rebalance scope, not global), and the
   bucket-rebalance ceremony adds complexity for no observed benefit.
   The plain base-62 lexicographic algorithm in D3 is LexoRank
   without the bucket layer.
4. **CRDT-native ordering (Yjs `Y.Array`, Automerge `List`)** —
   rejected: would require replacing the entire FIFO replay model
   (ADR-0010) and the SQLite row-per-item model (ADR-0008) with a
   CRDT runtime. Out of scope; revisit only if true real-time
   multi-cursor editing becomes a requirement.

## Gates Touched

- **New gates:**
  - `G-21-SORTORDER-STRING-ONLY` — enforces D1 (`Item.SortOrder` is
    `TEXT`/`string` everywhere; any `number`/`int`/`float` typing
    fails CI).
  - `G-21-SORTORDER-BASE62-ALPHABET` — enforces D2 (`0-9A-Za-z`
    only; no Unicode, no locale collation).
  - `G-21-INSERT-NO-SIBLING-MUTATION` — enforces D4 (insert/move
    writes exactly one `SortOrder` row).
  - `G-21-REBALANCE-PER-PARENT` — enforces D5 scope (rebalance
    touches only one parent's children, never global).
  - `G-21-REBALANCE-TRIGGER-64B` — enforces D5 trigger (64-byte key
    cap + 6-suffix cap).
  - `G-21-NO-NUMERIC-MIDPOINT` — explicitly forbids `(A+B)/2`,
    `parseFloat(SortOrder)`, or any arithmetic on `SortOrder`.
  - `G-21-LWW-ID-TIEBREAK` — enforces D6 (identical `SortOrder`
    rows resolve via `(ServerTs, UserId, Item.Id)`).
- **Modified gates:** `G-04-WIRE-PASCALCASE` clarified — `SortOrder`
  serialises as a string, not a number.
- **Endpoints locked:** `(none)` — `SortOrder` is a payload field on
  every Item-shaped response governed by ADR-0004.
- **DDL identifiers locked:** `Item.SortOrder` (`TEXT NOT NULL`),
  `Item_ParentId_SortOrder` (composite index).

## Supersedes / Superseded-By

- **Supersedes:** `(none)` formally; **deprecates** the numeric
  `(A+B)/2` + `gap < 0.0001` description in
  `mem://features/editor-core` and the `number (fractional)` typing
  in `spec/31-app/01-features/01-information-model.md` line 92.
- **Superseded-By:** `(none)`
