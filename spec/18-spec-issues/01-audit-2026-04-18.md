# Spec Audit — 2026-04-18

> **Version:** 1.0.0  
> **Updated:** 2026-04-18

---

## Summary

Audit pass over `spec/` with focus on `spec/31-app/` and `spec/32-ui-design/` after the recent restructure, plus a sweep of the wider spec root. **18 distinct issues** found, grouped into **6 themes**.

If the current spec is handed to an AI as-is, the **estimated failure / drift probability is HIGH (≈55–65%)** — driven mainly by I-01, I-02, I-03, I-09, and I-12 below. The split of `31-app/` and `32-ui-design/` is structurally sound, but the surrounding root is internally inconsistent and contains overlapping app-domain folders that will confuse any agent.

## Theme A — Root Numbering & Module Overlap

### I-01 — Numbering gap 18–20 in fundamentals range  *(Critical)*

`spec/` jumps from `17-generic-update/` directly to `21-app/`, leaving slots 18–20 unused. The spec authoring guide requires contiguous numbering.

- Affected: `spec/` root
- Impact: scanners report gaps; agents assume missing modules

### I-02 — Two parallel app trees: `21-app/` vs `31-app/`  *(Critical)*

`spec/21-app/` (declared "single source of truth for app-specific content") and `spec/31-app/` (the actively maintained WorkFlowy app spec) overlap in purpose. `21-app/` is essentially empty (`"No app-specific specs added yet"`) but its overview rule says all app content belongs there.

- Conflict: which folder is canonical?
- Impact: AI will pick the wrong root and write specs in the empty one

### I-03 — Two parallel design trees: `24-app-design-system-and-ui/` vs `32-ui-design/`  *(Critical)*

Same pattern: `24-app-design-system-and-ui/` is a stub (only `00-overview.md` + `99-consistency-report.md`), but `32-ui-design/` holds the real content.

### I-04 — Two parallel database trees: `04-database-conventions/` + `23-app-database/`  *(High)*

Three database-related folders exist (`04-database-conventions/`, `05-split-db-architecture/`, `23-app-database/`) without a clear hierarchy stating which is foundational vs app-specific.

### I-05 — Numbering gap 25–30 in app range  *(Medium)*

App range is `21–24` then jumps to `31–36`. Either the range definition is wrong or modules were moved. Either way, scanners flag it.

## Theme B — Header & Metadata Format

### I-06 — Inconsistent header style: blockquote vs plain  *(High)*

`.lovable/memory/docs/specifications.md` mandates the blockquote form:

```
> **Version:** X.Y.Z  
> **Updated:** YYYY-MM-DD
```

But `spec/01-spec-authoring-guide/02-naming-conventions.md` (lines 117–123) documents the **non-blockquote** form, and many existing files (e.g. `spec/22-app-issues/00-overview.md`, `spec/24-app-design-system-and-ui/00-overview.md`) use **`AI Confidence`** and **`Ambiguity`** fields that the spec authoring guide forbids ("No other metadata fields allowed").

- 14 files in the just-restructured `31-app/` and `32-ui-design/` use the non-blockquote form on `99-consistency-report.md`.
- Two competing rules in two memory/spec sources is the deeper bug.

### I-07 — Forbidden metadata fields still present in old folders  *(Medium)*

Files like `spec/21-app/00-overview.md`, `spec/22-app-issues/00-overview.md`, `spec/23-app-database/00-overview.md`, `spec/24-app-design-system-and-ui/00-overview.md` carry `**AI Confidence:**`, `**Ambiguity:**`, `**Status:**`, `## Keywords`, `## Scoring` blocks. The current rule says these are not allowed.

### I-08 — Version inconsistency across siblings  *(Low)*

`spec/31-app/00-overview.md` is `v1.2.0`, but its child `spec/31-app/01-features/00-overview.md` is `v1.0.0` despite being created in the same restructure. No defined version-propagation rule.

## Theme C — Naming Violations

### I-09 — Underscore vs hyphen rule conflict  *(Critical)*

Two coding-style sources contradict each other:

- `.lovable/strictly-avoid.md` line 28: **"No underscores in identifiers."** (applied to code)
- `spec/02-coding-guidelines/08-file-folder-naming/00-overview.md`: Go uses `snake_case.go`, Rust uses `snake_case.rs`, C# uses `PascalCase.cs`.

For **spec files specifically**, the rule is kebab-case only. No spec file currently uses underscores (audit clean), but the guideline page itself shows underscored examples without scoping them clearly to source code, which will confuse future agents.

### I-10 — `.lovable/memory/` vs `.lovable/memories/`  *(High)*

`.lovable/strictly-avoid.md` and `mem://index.md` correctly use `.lovable/memory/` (singular). But `spec/01-spec-authoring-guide/02-naming-conventions.md` line 10 references **`.lovable/memories/`** (plural) — the explicitly forbidden form.

### I-11 — Reserved-prefix table omits 18  *(Low)*

`spec/01-spec-authoring-guide/02-naming-conventions.md` reserves `00, 96, 97, 98, 99` but does not document any reserved meaning for the new `18` slot used by this folder.
